# Claims ledger

Chorus is an offline-first talking picture board for a non-speaking child. The child taps words and the device speaks them. Adults edit the board from their own devices, and Serverpod 4.0.4 with the experimental `serverpod_offline_sync` module 0.0.10 keeps the copies in step.

This file lists what the public documents of Chorus say, and what proves each statement. It was rewritten on 14 October 2026 between 16:30 and 18:00 UTC against:

- branch `wave6` at `b41ac5c`, the build deployed to Serverpod Cloud at 15:25 UTC;
- [`device-log.md`](device-log.md), up to and including "14 October 2026, late afternoon";
- the README at `f6479f7`, [`DESCRIPTION.md`](DESCRIPTION.md) at `06cdc0a` and [`TRY-IT.md`](TRY-IT.md) at `0f2c106`, each rewritten by another hand during this check;
- the landing page (`chorus_server/web/landing/index.html`) and [`voiceover.md`](voiceover.md) at `64e5d1b`, and [`feedback-form.md`](feedback-form.md) and [`post-draft.md`](post-draft.md) as rewritten in this check.

The review fixes listed at the end of the device log were being made in other branches during this check. Rows that depend on them say so. Re-check those rows after the final deploy.

No child, parent or clinician has used Chorus. The child in its story, Maya, is a persona, and so is every adult. Nothing in the project is a clinical claim.

## How to read it

There is one table per public document, and one for the features added on 14 October, which every document describes. Each row quotes or names a claim, gives the evidence, and gives one status.

| Status | Meaning | How the documents may word it |
|---|---|---|
| device-verified | A person saw it on real hardware against the deployed server. It has a row in [`device-log.md`](device-log.md). | "Checked". |
| automated-test only | A named automated test exercises it. Nobody has seen it on a device. | "Built and tested". Never "checked". |
| code only | It was read from the source, the configuration or another first-hand record during this check. No test is named and nobody has seen it on a device. | As a plain statement of how it is built, or left out. |
| unverified | No first-hand record was found. It is the author's own statement, a plan, or something not yet tried. | Only as the author's own statement, or left out. |
| false | A first-hand record contradicts it as written. | Must be changed before submission. |

Where a claim was seen on one device and is written about another (seen in a browser, described on a phone), the evidence column says so. Every device check on 14 October from 15:25 UTC was in Edge on the Mac only: the phone still ran the 13:02 UTC build. Every device check on Cloud so far used one account, the participant's, on both devices; three demo sign-ins were used only on a local server.

The documents no longer mark sentences with square brackets. A feature that has not been seen on a device is called "built and tested", or left out.

"Sync tests" are in `chorus_server/test/sync/`. They run a real server on an embedded PostgreSQL and one SQLite replica file per device. T1 to T10 are the scenarios described in [`spike-results.md`](spike-results.md). `practice_clash_test.dart` covers "Try a clash" the same way.

## Found false or at risk in this check

Each needs a decision before submission. None of these files is in this writer's hands.

1. **"Remove from circle" is still on in the deployed build.** The README and the description say it is switched off for the deadline. At `b41ac5c`, `circleMembersEnabled` is `true` in `chorus_ui/lib/features/flags/w2.dart` and the guardian sees "Remove from circle". The switch is being added in the fix branch (`removeFromCircleEnabled`). The sentence becomes true only with that deploy. Rows R40, D16.
2. **"15 of them were added on 14 October."** (README) Migration `20261014151037130` creates 15 server-only tables; migration `20261014094307220`, the same morning, created three more (`weekly_summary`, `word_log_setting`, `word_use`). So 18 were added on 14 October. The description's "15 server-only tables added" is right of the research-led features only. Rows R33, D13.
3. **The film names products other than Chorus and Serverpod.** The rule in `voiceover.md` is that narration and captions name only Chorus and Serverpod. Scene 6 says "Postgres", and the closing card says "Android app and code on GitHub". Either reword those lines, or narrow the rule to "no other product is promoted". Row V1.
4. **"Ms Lee can ... see what was modelled and what Maya said herself."** (`voiceover.md`, scene 5 draft.) If Ms Lee is the teacher, as in the earlier script, the server refuses her "This week": `chorus_server/test/integration/summary_test.dart`, "when a guardian or a therapist asks then they get the week, and a teacher, a partner and a stranger are refused." Give that line to the therapist. Row V9.
5. **The glow on another device.** The landing page ("Search from your phone and the button glows on her board") and the film's scene 5 draft ("make it glow on Maya's board") state the word finder's glow on the child's board. The device log says "The glow on another device was not checked." Rows L13, V9.
6. **"Works in any modern browser."** (landing page) Every browser check was in Microsoft Edge on macOS, plus one second browser that opened the view-only and paper-copy pages. Row L24.
7. **"Delete the word log"** left the sitter's taps and the report copies at `b41ac5c` (device log, review findings). The README's sentence says it removes the log "with the weeks worked out from it", which is true; it does not mention the other two. Row R55.
8. **The film has no persona line.** `voiceover.md` opens "This is Maya" and never says she is a persona. The landing page, README and description all do. A caption in scene 1 would close the gap. Row V5.
9. **Small wording points.** `TRY-IT.md` says the server adds the practice partner "to your circle"; it joins the circle's sync space only, and is never a circle member (row T11). It says the partner's limit is "to one board each hour"; the limit is per circle (row T35). The README deploys with `scloud deploy`, while the device log and `docs/BUILD.md` use `serverpod cloud deploy` (row R49).
